## 11. Codexレビューを反映した補足・修正（2026-11-03、読み取りレビュー1往復）

- **「表示14番・推論15番」の見分け方を強める（§5 段7・§1 の訂正）**: モデルの回答や上限の挙動は口座の判別にならない。cfg14 の `/usage` も15番への計上を示さない。判定は、プロキシ側で「その要求の上流送信に、15番と確認した認証が使われた」ことを内部で真偽として確かめる（値は出さない）。使用量画面で補強する場合も、本番・13945 の利用や表示の丸めが交じるので、それだけでは未確認扱いにする。
- **/feedback の経路の推定を直す（§5 段3・§9 の訂正）**: 「プロキシに記録が無ければ api.anthropic.com 直結」とは言えない。CLI の `/feedback` と HTTP のパス名が対応する保証も無い。送信時刻とプロキシの全要求を突き合わせ、観測が無ければ「プロキシ通過は観測されず、直接の宛先は未特定」と書く。受付 ID は送信成功の証拠であって、経路や認証口座の証拠ではない。
- **「/feedback の認証を替えていない」ことの観測を定義する（§5 段8 の追加）**: method・path・status・時間だけでは足りない。対象要求について「受信時の認証＝送信時の認証」という真偽値を内部比較で出す（トークンやそのハッシュは記録しない）。
- **15番トークンの読み取り方を具体化する（§3 の追加）**: 完全なサービス名・acct・対象 Keychain を限定し、一意（1件だけ）を確認する。項目が JSON なら、access token を取り出すときに refresh token を含む全体を内部で読む可能性があることを明記する。既定項目やファイルへの fallback、値の stdout/stderr・例外への混入、プロキシ自身の refresh は禁止。読めない・期限切れ・401/403 のときは停止する。
- **同一口座の使用量への影響は残る（§9 の訂正）**: 本番・13945 に直接触れなくても、同じ15番を使えば使用量は消費される。15番の事前 `/usage` を 13945 へ入力して確認しない。試験用タブ・プロキシの見分け方（タブ名、ポート、プロセス）を明記する。「本番に何も残らない」「設定ファイルは変わらない」は言い切らない（Claude Code 自身の保存・refresh、同一口座へのサーバー側影響は別）。
- **予定外の Keychain 項目は削除しない。cfg14・cfg15 も T3 の後片付けで削除しない（§8 の訂正）**: 予定外の項目は停止・報告のみ。削除は事前登録した試験項目だけ。cfg14・cfg15 は後片付けで消さないと明記する。
- **T3 は「再起動なしの切替」を検証していないと限定する（§0・§5 の訂正）**: 段1 を終えて段2 を別に起動するので、確かめられるのは2つの構成の比較まで。結論をそこに限る。再起動なしの切替・復帰を見たいなら、同じセッションを保ったまま上流を切り替える段を別途設ける（別途計画）。
- **差し替えと中止条件を厳しくする（§3・§7 の追加）**: 差し替えの対象は「POST かつ正規化した pathname が /v1/messages」だけに限定する。送信先は接続の前に固定で検証し、別ホストへの redirect や 14番・37891 への fallback を禁止する。予期しない確認画面・認証の不一致・ストリーム切断・タイムアウトでも停止し、終わらせるのは対象の試験プロセスだけにする。/feedback は「添付しない」を選べないとき、または未承認の診断情報が添付されそうなときは送信を止める。
