- 結果: 起動したままのセッションの `/status` と `/usage` が、**数秒で新しい口座に変わった。再起動なし。**

## 4. 事実・推測・未検証の分け方

**事実（実機で観測）**
1. 同じフォルダに別のプロセスから正規の `/login` をすると、起動中のセッションが数秒で追従する（10/27）。
2. 同じフォルダの Keychain 項目と `oauthAccount` を直接書き換えても、起動中のセッションが追従し、普通の操作ができる。戻す切り替えも0秒（10/29）。
3. 正規ログインのフォルダは、Claude Code が自分でトークンを更新し、16時間以上〜数日使える（試験2・試験3）。
4. 正規ログインなら、サブスクリプションの正しい表示になり、`/feedback` も送れる（試験2）。
5. `USER` が無い起動では acct=unknown になり、ログアウト扱いになる（試験2）。
6. 直接書き換えた 10/29 の試験は、約16.5時間後に `Not logged in` になった。その間、項目の更新時刻は進まなかった。

**推測（理由はあるが確定していない）**
- 10/29 の `Not logged in` の原因候補: ①コピーした実行ファイルで Keychain の確認画面が出て、夜間の自動更新を保存できなかった（10/31 の再実施で毎回確認画面が出たことから。中）、②書き戻した認証情報が古い世代で、更新に失敗した（中）、③プロセスが古い情報を覚えていた（中）、④USER と acct の食い違い（中）。
- `/usage` が追従したので、実際の通信も新しい口座で行われていたはず。

**未検証**
- 切り替えた後に、長時間（12〜36時間以上、自動更新を1回以上またいで）使い続けられるか。
- 通常の実行ファイル＋`USER` をそろえた条件での、切り替えと長時間の維持。
- 切り替えた後の `/feedback`。
- 実際の課金・使用量が新しい口座に計上されるか（Anthropic の使用量画面での確認）。
- 動作中のサブエージェント・バックグラウンドの作業・長い応答の途中で切り替えたときの動き。
- 1フォルダに多数（10〜100）のセッションがあるときの一斉追従。
- 同じ口座の更新がぶつかったとき（ローテーターと Claude Code が両方更新しようとしたとき）。
- Claude Code の自動アップデートで挙動が変わらないか（2.1.310 → 2.1.317 の間で再確認していない）。
