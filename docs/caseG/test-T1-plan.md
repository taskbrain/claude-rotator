## 11. Codexレビューを反映した補足・修正（2026-11-03、読み取りレビュー1往復）

- **「本番に何も残らない」「設定ファイルは変わらない」とは断言しない（§9 の訂正）**: フォルダを分けても、同じ口座を使う以上、その口座のサーバー側・使用量には影響しうる。Claude Code 自身の保存・refresh も起きる。§9 は「本番の設定ファイルと Keychain 項目には書かない」までに限定し、同一口座への影響は残ると明記する。
- **確認スクリプトは「名前だけ替えた流用」にしない（§3-5 の訂正）**: 試験3の `caseG-test3-check.sh` は本番 `~/.claude.json` への `stat` や、旧バージョンを使うプロセスの広い探索を含む。T1 用は、見る対象（この試験の項目名・PID・フォルダ）を名指しした専用スクリプトを別に作り、本番ファイルを stat しない。PID が生きているだけでは「認証が正常」「影響なし」の証明にならないと明記する。
- **予定外の Keychain 項目は削除しない（§8 の訂正）**: 予定外だからこそ試験の持ち物と確認できない。見つけたら停止・報告のみ。削除は、事前に名前を登録した試験項目だけに限る。
- **T1-2 の移す順序の穴（§10 の訂正）**: 「レーンへ書く→レーンにあった分を保管」では、上書きの前に旧レーンの最新状態を退避・保護する手順が抜ける。順序は「①移す元と旧レーンの最新を退避保存 → ②競合検出（この間に背景 refresh が走っていないか）→ ③レーンへ書く → ④結果確認、不明なら停止して記録」とする。人の区切り確認だけでは背景 refresh を排他できないので、退避と競合検出を機械側に入れる。
